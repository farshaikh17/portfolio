# Farhan Shaikh — portfolio

**Live site: [https://portfolio-indol-gamma-6pgrxbnt7h.vercel.app](https://portfolio-indol-gamma-6pgrxbnt7h.vercel.app/)**

A professional portfolio for technical operations, implementation, CRM/automation and AI-assisted systems delivery. The site explains responsibilities and decisions with evidence, rather than presenting Farhan as the sole author of all implementation code.

## Stack and architecture

Dependency-free static site generated by Node.js. Semantic HTML, responsive CSS, no client JavaScript, no database and no backend. Content is rendered at build time into `dist/`; case studies have their own routes. This keeps the site fast, portable and easy to review. Node 22 or newer; no dependencies or application secrets are required.

## Local development

```sh
npm run build
npm test
npm run dev
```

Open http://127.0.0.1:4173. Edit `build.mjs` for content and shared layouts; edit `styles.css` for presentation. Rebuild after edits.

## Routes

- `/` — work, approach, leadership, experience, capabilities and contact
- `/work/miami-goes-local/` — professional/company case study
- `/work/parenthood/` — personal experiment case study
- `/404.html` — not-found experience

## Deployment

Import **this personal repository** into an explicitly verified personal Vercel workspace. Select Other framework, build command `npm run build`, output `dist`, repository root. The included `vercel.json` configures these options and security headers. There are no application secrets or bindings to supply. Canonical URLs, `og:url` and the sitemap use Vercel's `VERCEL_PROJECT_PRODUCTION_URL` at build time; an optional HTTPS `SITE_URL` origin can override it if a custom domain is added. `robots.txt` links to the generated sitemap. No domain purchase is needed.

Production is deployed from `main` in Farhan Shaikh's personal Vercel Hobby workspace (`farhan-shaikh1`), connected to `farshaikh17/portfolio`. Pushes to `main` trigger a new production deployment. No employer workspace is used.
